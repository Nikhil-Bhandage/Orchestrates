# Solved-sample financial-state diagnostic

Generated by `code/evaluation/sample_diagnostics.py`. This is a diagnostic/regression artifact only; solved rows are not used as prediction labels.

## Scope and architecture

- `data_layer.py` loads losslessly and indexes users, requests, events, options, messages, images, links, and fixed exchange rates.
- `canonical_events.py` keeps one event per `event_id`, resolves the existing OCR-first/cache-backed image amounts, and records explicit cash eligibility.
- `financial_timeline.py` forecasts supported recurrence, converts every eligible cash flow into home currency using exact source settlement-date rates (or the latest fixed prior rate only for synthetic projections), and performs RMQ/prefix/two-pointer simulation.
- `evidence_resolution.py` builds indexed `RequestContext` objects, extracts typed facts without creating transactions, records conflicts, and applies only explicit amount-bearing payroll/rent amendments to existing timeline entries.
- `test_golden_samples.py` reruns all 25 solved samples deterministically and checks output-field invariants without copying solved labels into the pipeline.

## Evidence and rule decisions

- Blank event amounts are resolved only through the existing image evidence resolver; all 16 image-linked blank amounts have cached evidence and remain tied to their original event IDs.
- Messages are relevant when directly request-linked, event-linked, or user-wide and sent by the request date. Evidence is never counted as cash and never duplicates a linked transaction.
- Explicit settlement/amendment/termination facts are represented; pending credits, pending prizes/refunds, unrealized valuations, unapproved commissions/bonuses, and service-provider pending balances remain excluded.
- Confirmed payroll amounts with defensible dates/scopes amend existing salary projections. “Next/first/temporary/reduced” wording is one cycle; explicit recurring increases/resumptions apply to future salary entries. Date replacements move the first existing salary projection rather than adding a credit.
- A pending debit remains reserved exactly once. Historical settled events are not replayed into the supplied current balance. Same-date natural events precede requested payments.
- Foreign-currency source events require the supplied exact settlement-date rate. Synthetic recurrence dates use the latest supplied fixed rate on or before the projection date because the table is monthly; no live rate is used.

## Findings

- All 25 solved samples were reconstructed; two evidence-adjusted safe amounts exactly equal the solved amount field. The remaining differences are preserved in `sample_diagnostic.json` rather than hidden.
- The strongest concrete implementation discrepancy was foreign-currency arithmetic; request_25 changed from an unusable source-unit calculation to a deterministic IDR value after USD→IDR conversion.
- Five solved samples reference images directly; the global canonical store covers all 16 image-linked blank amounts. Image evidence changes event amount resolution only and does not add cash rows.
- Evidence extraction found payroll amount/date facts, a revised payroll date, a terminated seasonal contract, a rent increase, an internal-transfer confirmation, and pending/unrealized/settled-proceeds facts. The adjusted timeline retains the same event-ID set.
- Many rows differ because the current primitive intentionally answers “safe one-time full payment today,” while solved recommendations choose `wait`, `installments`, `partial_payment`, or permitted spending changes. Those differences belong to candidate-plan generation and deadline simulation, not to evidence resolution.
- Remaining state-policy differences are concentrated in conservative variable-spending forecasts and benchmark-specific balance interpretation. These are documented per row with projection kinds, minimum balances, relevant incomes/expenses, and raw-vs-adjusted values; no sample-specific hardcoding was added.

## Complexity and data structures

- Direct evidence/event lookups are O(1) average through dictionaries; event-link closure is linear in the user’s event graph.
- Timeline construction sorts entries and projections, then builds prefix sums, suffix minima, and an RMQ segment tree. One-time safety queries are O(log n) in the cached path.
- Exact plan simulation remains the existing O(n + p) natural-event/payment two-pointer sweep; evidence adjustment rebuilds only the affected timeline indexes.
- Memory is O(n) per user timeline and O(e) for indexed evidence/events.
